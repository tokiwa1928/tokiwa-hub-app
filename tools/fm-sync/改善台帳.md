# FileMaker 改善台帳

FileMaker を改善し、その内容を Tokiwa Hub に展開していくための記録。

**この台帳の役割**

- 改善を「ルール」として書き残す。Hub への移植を設計ではなく作業にする
- 何を変更したかを残し、**戻し方**を明示する
- Hub 側が遅れていないかを一覧で見えるようにする

---

## 作業の決まりごと

**① 変更は追加だけ**

既存の項目・レイアウト・計算式は変更しない。新しく足す。
どうしても既存を変える必要が出たら、この台帳に理由と元の定義を残す。

**② 変更前に必ずスナップショット**

```
fm-snapshot.cmd --note "○○を追加する前"
```

変更後にもう一度取り、`fm-snapshot.cmd --diff` で差分を確認する。
意図しない変更が混ざっていないかは、これで機械的に分かる。

**③ 1回に1つ**

複数を同時に変更しない。変更 → 照合 → 次。

**④ 新規レイアウトは `Hub` を頭に付ける**

既存レイアウトと混ざらないようにする。（例: `Hub連携`, `Hub連携_検証`）

**⑤ ルールは必ず両側に実装し、突合で証明する**

FileMaker 側の計算と Python 側の実装が同じ結果になることを、
実データ数千件で照合してから「完了」とする。

---

## 安全網

| 層 | 内容 | 復元できるもの |
|---|---|---|
| 1 | FileMaker Cloud の自動バックアップ | ファイル全体（要・管理コンソール） |
| 2 | 設計スナップショット（`fm_snapshot.py`） | 何が変わったかの特定。戻す手順の根拠 |
| 3 | 台帳の「戻し方」欄 | 個々の変更の取り消し |

**層2・層3は「何を戻せばよいか」を確定させるもので、自動では戻しません。**
ファイル全体の復元が要る事態には層1が必要です。

## 改善の記録

### 001. ノート用タイトル

| | |
|---|---|
| 日付 | 2026-09-08 |
| 目的 | 伝票をノートやフォルダの名前にするとき、毎回手で打っていたのをなくす |
| 種別 | ルール（計算フィールド） |

**規則**

```
伝票番号_得意先名(ユーザー名)_品名

・ユーザー名が空なら括弧ごと省く
・品名は 製品名、無ければ 物品名
・空の部分は区切り文字ごと省く
・改行・タブは取り除く（データに混入している）
・全角スペースは半角に寄せて前後を落とす
・ファイル名に使えない文字 \ / : * ? " < > | は - に置換
```

**FileMaker 側**

- `受注データ` に計算フィールド `ノート用タイトル`（テキスト・非保存）
- 得意先名は `ExecuteSQL` で `得意先マスタ` から引く（リレーション不要）
- `受注データA` レイアウト（トキワ印刷AP）に表示欄とコピーボタンを配置
  - 欄: 左165 上74 幅200 高14
  - ボタン: 左376 上72 幅81 高25 / 動作 = 単一ステップ `コピー [選択; 受注データ::ノート用タイトル]`
  - 欄の設定: フィールド入力「ブラウズモード」「入るときに全内容を選択」をオン

**Hub 側**

- `tools/fm-sync/fm_export.py` の `note_title()` / `clean()`
- 書き出し CSV・JSON に `ノート用タイトル` 列として出力

**照合**

テーブル全域から2,000件を抽出して比較 → **100%一致**

**戻し方**

1. `受注データA` レイアウトでボタンと欄を選択して削除 → 保存
2. ファイル > 管理 > データベース > フィールド で `ノート用タイトル` を削除
3. `fm_export.py` の `note_title` 呼び出しを外す

いずれも追加したものを消すだけで、既存のデータ・項目には影響しない。

## 削除候補（まだ消さない・赤で印だけ付ける）

消す前に必ず「一定期間 赤くしておく」→「誰も困らないことを確認」→「消す」の順で進める。
消した瞬間に困る人が出ないようにするため。

### D-001. 作業時間の実績欄

| | |
|---|---|
| 日付 | 2026-09-08 |
| 場所 | トキワ印刷AP / `受注データA` レイアウト 左下 |
| 状態 | **赤で印を付けた（2026-09-08 保存済み）**。削除はしていない |

**対象**

```
          製作   ミシン   オンデマンド   梱包   合計P   合計作業時間
          [日付] [日付]  [日付]      [日付]
  前回P   [   ] [   ]  [   ]      [   ]  [   ]  [   ]
  実績P   [   ] [   ]  [   ]      [   ]  [   ]  [   ]
```

**特定できた項目（受注データ）**

- `ミシン_time`
- `オンデマンド_time`
- `合計作業時間`
- `合計作業時間p表記`

**レイアウト上で確認した配置（24個）**

```
見出し     製作 / ミシン / オンデマンド / 梱包 / 合計P / 合計作業時間
日付の行   作業伝票 × 4列（関連項目）
前回P の行 前回の製作… / 前回のミ… / 前回のオ… / 前回の梱… /
           前回の合計作業… / 前回の合計作業時間
実績P の行 製作_time / ミシン_time / オンデマンド_time / 梱包_time /
           合計作業時間_… / 合計作業時間
```

`製作` `合計P` `前回P` `実績P` という名前の項目は `受注データ` に存在しない。
見出しは静的テキスト、中身は上記の `_time` 系および `前回の…` 系だった。

**進め方**

1. **文字色を赤にして保存（2026-09-08 完了）** — レイアウトの書式のみ。データ・項目は無傷
2. しばらく運用して、誰も使っていないことを確認
3. 問題なければレイアウトから削除
4. さらに時間をおいて、項目そのものを削除するか判断

**戻し方**

同じ24個を選択して文字色を黒に戻す。書式だけなので影響なし。

## 検討中の改善

### トピー現品票のリピート判定

前回伝票番号を人が探している作業を、判定ルールで置き換える。

```
前回あり・原稿修正あり → リピート / 仕様変更:無 / 版下修正:有
前回あり・原稿修正なし → リピート / 仕様変更:無 / 版下修正:無
前回なし（類似コピー） → 新規   / 仕様変更:無 / 版下修正:無
印刷色が「見本」      → 実物を確認（人の判断が要る箇所として残す）
```

必要な項目は `Hub連携` レイアウトで既に読める:
`前回伝票番号` `前回起票日` `ロット区分` `仕様変更` `版下変更`
