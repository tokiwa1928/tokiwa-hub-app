# FileMaker 中継

Hub の画面から FileMaker のデータを直接読み書きするための中継。

```
Hub（ブラウザ）→ この中継（GAS）→ FileMaker Cloud Data API → トキワ印刷DB
```

**プロジェクトの作成・コードの配置・公開は clasp で済んでいます。**
残っているのは、①②（秘密を扱う分）と、③（Hub の画面から呼ぶための準備）です。

画面は2つの置き場所があり、中身は同じものです。

| 置き場所 | ファイル | 呼び方 | サインイン |
|---|---|---|---|
| Apps Script が配る | `juchu.html` | `google.script.run` | ページ自体が社内限定 |
| Hub に置く | `tools/fm-juchu-hub.html` | `fetch` | ③ の設定が要る |

どちらも `python tools/fm-relay/build_juchu.py` で `tools/fm-juchu.html` から作ります。
**Hub 版が使えるようになったら、Apps Script 版は役目を終えます。**

## 残っている作業

### ① スクリプトプロパティを入れる

更新トークンは画面にもチャットにも出しません。このPCで次を実行すると
**クリップボードに入ります。**

```bat
C:\Users\honda\dev\tokiwa-hub-app\tools\fm-sync\更新トークンをコピー.cmd
```

編集画面 → **⚙ プロジェクトの設定** → 一番下 **スクリプト プロパティ** →
**スクリプト プロパティを追加**

| プロパティ | 値 |
|---|---|
| `FM_REFRESH_TOKEN` | （上でコピーしたもの） |
| `ALLOWED_DOMAIN` | `tokiwap-group.com,tokiwap.co.jp` |
| `DEV_KEY` | 適当な長い文字列（**動作確認が済んだら消します**） |
| `WEB_CLIENT_ID` | ③ で作るクライアントID（Hub 版を使うなら） |

`LOG_SHEET_ID` は任意。入れると「誰がいつ何を書いたか」がそのシートに残ります。

> `ALLOWED_DOMAIN` は**社員が Google にサインインするときのドメイン**です。
> 本多さんの Claris ID は `@tokiwap.co.jp`、clasp は `info@tokiwap-group.com` で
> 通っているので、既定で両方を許しています。片方しか使っていなければ、
> 使っている方だけにしてください。ここに無いドメインの人は、URL を知っていても通れません。

### ② スクリプトを承認する

編集画面で、関数の一覧から **`セットアップ確認`** を選んで **実行**。

- 初回に権限の承認画面が出ます。承認してください。
  **これをしないと外から呼べません**（いまウェブアプリが 403 なのはこれが理由）
- 同時に、プロパティが正しいか・FileMaker につながるかを確かめて
  **実行ログ**に出します

出てほしい内容:

```

○ ALLOWED_DOMAIN : tokiwap-group.com,tokiwap.co.jp
○ Claris のトークン取得  ○ Data API のセッション
○ レイアウト Hub受注   書ける項目 198 / 読むだけ 64
○ 1件の検索（全 73,000件台）
すべて通りました。中継は使える状態です。
```

### ③ Hub から呼ぶ準備（OAuth クライアントID）

Apps Script が配る版だけを使うなら、ここは要りません。
**Hub（`tokiwa1928.github.io`）の画面から FileMaker を読み書きするときだけ必要**です。

Hub は公開のページなので、開いた人が社員かどうかを Google に確かめてもらいます。
そのための「このページ用の名札」を1つ作る作業です。作るのは一度だけ。

1. <https://console.cloud.google.com/> を **info@tokiwap-group.com** で開く
2. 上のプロジェクト選択 →「新しいプロジェクト」→ 名前は `Tokiwa Hub` などで作成
3. 左メニュー **API とサービス** → **OAuth 同意画面**
   - User Type は **内部**（社内だけに配るのでこれでよい）
   - アプリ名 `Tokiwa Hub`、サポートメール・デベロッパー連絡先に自分のアドレス
   - スコープは何も足さなくてよい（名前とメールしか使いません）
4. **認証情報** → **認証情報を作成** → **OAuth クライアント ID**
   - 種類: **ウェブ アプリケーション**
   - 名前: `Tokiwa Hub 受注入力`
   - **承認済みの JavaScript 生成元** に次の2つを追加

     ```
     https://tokiwa1928.github.io
     http://127.0.0.1:8765
     ```

     （下は手元で試すためのもの。要らなければ入れなくてよい）
   - リダイレクト URI は**空のままでよい**
5. 出てきた **クライアント ID**（`....apps.googleusercontent.com`）を控える
   - これは**秘密ではありません**。ページに書いてよいので、チャットで送っても構いません
   - 一緒に出る「クライアント シークレット」は**使いません。誰にも渡さないでください**

控えたクライアント ID を2か所に入れます。

- スクリプトプロパティ `WEB_CLIENT_ID`（①と同じ画面）
- `tools/fm-relay/build_juchu.py` の `CLIENT_ID = ''`

入れたら組み立て直します。

```bat
python C:\Users\honda\dev\tokiwa-hub-app\tools\fm-relay\build_juchu.py
```

最後に、ウェブアプリのアクセス設定を **「全員」** に変えます
（`appsscript.json` の `access` を `ANYONE_ANONYMOUS` にして `clasp push` → 再デプロイ）。
公開されるわけではありません。中継が ID トークンを確かめるので、
**社内アカウント以外は URL を知っていても何もできません。**
`WEB_CLIENT_ID` を入れておくと、社員が別のサイトでもらったトークンも弾きます。

> アクセス設定を「全員」に変えると、**Apps Script が配る版は使えなくなります**
> （`Session.getActiveUser()` が誰か分からなくなるため）。
> Hub 版が動くのを確かめてから切り替えてください。

## 安全のしくみ

| | |
|---|---|
| 誰が呼べるか | Google でサインインした許可ドメインのアカウントのみ |
| 書ける項目 | **入力可の項目だけ**。計算フィールドと伝票番号は送られても捨てる |
| 二重更新 | 保存時に `modId` を送る。誰かが先に更新していれば FileMaker が弾き、画面に知らせる |
| 記録 | `LOG_SHEET_ID` を入れると、誰がいつ何を書いたかが残る |

Hub は公開の GitHub Pages にあるため、**合鍵をページに埋め込む方式は使いません。**
ウェブアプリのアクセス設定は「全員」ですが、中継が Google の ID トークンを
検証するので、社外の人は URL を知っていても何もできません。

## 動作確認が済んだらやること

- **`DEV_KEY` を削除する。** これがある間は、鍵を知っていればサインイン無しで通れます
- 実運用に入る前に、中継用の Claris ID を別に用意して `FM_REFRESH_TOKEN` を差し替える

## 更新トークンが切れたら

有効期間は1年です。切れると

> Claris のトークンを更新できません（更新トークンの入れ直しが要ります）

と返します。`tools/fm-sync/fm-connect.cmd` で入れ直し、①をやり直してください。
